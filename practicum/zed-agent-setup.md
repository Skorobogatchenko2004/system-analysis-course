# Настройка среды для работы с агентом в Zed

Эта инструкция поможет настроить локальную работу с файлами командного
репозитория: редактировать материалы лабораторной в Zed и обсуждать их с
агентом Codex. Настройка необязательна: можно продолжать работать через
браузер GitHub по инструкции курса.

Инструкция ниже — для Windows. Установщики и пункты меню Zed со временем
могут меняться; актуальные сведения — в [документации Zed для
Windows](https://zed.dev/docs/windows) и [документации внешних
агентов](https://zed.dev/docs/ai/external-agents).

## Что понадобится

- доступ к репозиторию команды на GitHub;
- [Zed](https://zed.dev/);
- [GitHub Desktop](https://desktop.github.com/) для клонирования репозитория,
  веток и отправки изменений;
- Codex, доступный через каталог внешних агентов Zed, и способ войти в
  аккаунт Codex.

## 1. Установите Zed и GitHub Desktop

Установите Zed с [официального сайта](https://zed.dev/) или откройте
PowerShell и выполните:

```powershell
winget install -e --id ZedIndustries.Zed
```

Установите также [GitHub Desktop](https://desktop.github.com/) и войдите в
свой аккаунт GitHub. Приглашение в репозиторий команды должно быть принято
под этим аккаунтом.

## 2. Склонируйте репозиторий и создайте ветку

В GitHub Desktop:

1. Выберите **File → Clone repository**.
2. Найдите репозиторий своей команды и выберите папку на компьютере, куда
   его сохранить.
3. Выберите **Current branch → New branch**, введите `lab1` и создайте
   ветку от `main`.
4. Нажмите **Publish branch**, если GitHub Desktop предложит опубликовать
   новую ветку.

Откройте эту папку в Zed через **File → Open Folder**. Открывайте папку
проекта целиком: так агент сможет учитывать контекст файлов репозитория.

## 3. Подключите Codex в Zed

1. Откройте панель агента: нажмите значок ✨ или найдите в палитре команд
   `agent: new thread`.
2. Откройте каталог агентов командой `zed: acp registry`. Если такой команды
   нет, откройте настройки агента (`agent: open settings`), страницу
   **External Agents**, нажмите **Add Agent → Install from Registry**.
3. Найдите и установите **Codex**.
4. Создайте новый диалог, выберите Codex и пройдите предложенный вход.

Codex в Zed — внешний агент: вход и настройки доступа принадлежат Codex и
зависят от версии интеграции. Подписка или API-ключ, настроенные для
встроенного Zed Agent, автоматически Codex не подключают. Подробности есть
в разделе [Codex в документации Zed](https://zed.dev/docs/ai/external-agents#codex).

## 4. Попросите агента подготовить черновик

Сначала объясните агенту, что вы исследуете, и попросите его задавать
вопросы, а не заполнять пробелы догадками. Например:

> Мы делаем первую лабораторную по системному анализу. Требуется выбрать
> наблюдаемую систему, описать и обосновать её границы, определить среду,
> заинтересованные стороны и их цели, сформулировать проверяемую цель
> системы, а после посещения записать три наблюдения. Помоги создать в
> папке `lab1/` черновики: `README.md` для записки, `stakeholders.md` для
> таблицы сторон и `context.mmd` для Mermaid-контекстной диаграммы. Сначала
> задай мне вопросы о системе и предложи структуру файлов. Не выдумывай
> факты, ответы участников и наблюдения; неизвестное отмечай как
> `[уточнить]`, наблюдения — как `[добавить после посещения]`.

Если полное задание лабораторной не лежит в командном репозитории, вставьте
его требования в сообщение или откройте задание отдельно и передайте
агенту нужный контекст. В работе можно попросить агента отредактировать
конкретный файл, объяснить диаграмму, проверить согласованность таблицы и
записки или предложить вопросы для следующего наблюдения.

## 5. Проверяйте работу и сдайте её

Агент может читать и изменять файлы проекта. Он не наблюдал вашу систему и
не разговаривал с её участниками, поэтому проверяйте все факты, выводы,
границы и подписи диаграммы сами. Не принимайте изменения, смысл которых
вам непонятен.

Перед сдачей:

1. Просмотрите изменённые файлы и diff в Zed или GitHub Desktop.
2. Замените все пометки `[уточнить]` и `[добавить после посещения]` своими
   данными. Убедитесь, что выводы подтверждаются наблюдениями.
3. В GitHub Desktop введите краткое описание изменений и нажмите
   **Commit to lab1**.
4. Нажмите **Push origin**, если ветка уже опубликована, или
   **Publish branch**, если это ещё не сделано.
5. На GitHub откройте pull request из `lab1` в `main` и сдайте его по
   инструкции курса.

Для следующей лабораторной создайте отдельную ветку (`lab2`, `lab3` и так
далее), чтобы каждая сдача была отдельным pull request.

Не отправляйте агенту пароли, ключи доступа, персональные данные или
закрытые материалы собеседников. Обезличивайте примеры и перед передачей
реальных данных внешнему сервису получите разрешение.
