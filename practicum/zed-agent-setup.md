# Рабочая среда: Zed или GitHub Codespaces

Для работы с файлами командного репозитория есть два подхода:

1. **Zed на своём компьютере.** Репозиторий хранится локально, а агент
   Codex подключается в Zed. Понадобятся Zed и GitHub Desktop.
2. **GitHub Codespaces в браузере.** Репозиторий открывается в облачной
   среде с редактором VS Code. Устанавливать редактор и Git не нужно;
   агента, если он нужен, настраивают отдельно.

Выберите один подход и пройдите его шаги от начала до конца. В обоих
случаях создавайте отдельную ветку для каждой лабораторной, проверяйте
изменения и сдавайте работу pull request в `main`. Работа через браузер
GitHub без среды разработки также остаётся доступна по инструкции курса.

## Подход 1. Zed и Codex на компьютере

Инструкции этого раздела — для Windows. Установщики и пункты меню могут
меняться; актуальные сведения есть в [документации Zed для Windows](https://zed.dev/docs/windows)
и [документации внешних агентов](https://zed.dev/docs/ai/external-agents).

### Установите программы и получите доступ к репозиторию

Понадобятся Zed, [GitHub Desktop](https://desktop.github.com/), аккаунт
GitHub и принятое приглашение в репозиторий команды.

Установите Zed с [официального сайта](https://zed.dev/) или откройте
PowerShell и выполните:

```powershell
winget install -e --id ZedIndustries.Zed
```

Установите GitHub Desktop и войдите в аккаунт GitHub, которому выдали
доступ к командному репозиторию.

### Склонируйте репозиторий и создайте ветку

В GitHub Desktop:

1. Выберите **File → Clone repository**.
2. Найдите репозиторий команды и выберите папку на компьютере, куда
   склонировать его.
3. Выберите **Current branch → New branch**, назовите ветку `lab1` и
   создайте её от `main`.
4. Откройте склонированную папку в Zed через **File → Open Folder**.
   Открывайте папку проекта целиком, чтобы агент видел его файлы.

### Подключите Codex в Zed

1. Откройте панель агента: нажмите значок ✨ или найдите в палитре команд
   `agent: new thread`.
2. Откройте каталог агентов командой `zed: acp registry`. Если такой команды
   нет, откройте настройки агента (`agent: open settings`), страницу
   **External Agents**, затем **Add Agent → Install from Registry**.
3. Найдите и установите **Codex**.
4. Создайте новый диалог, выберите Codex и выполните предложенный вход.

Codex — внешний агент со своими настройками входа и доступа. Подписка или
API-ключ, настроенные для встроенного Zed Agent, не подключают Codex
автоматически. Подробнее — в разделе [Codex в документации Zed](https://zed.dev/docs/ai/external-agents#codex).

### Работайте с агентом над лабораторной

Сначала расскажите агенту, какую систему исследуете, и попросите задавать
вопросы, а не заполнять пробелы догадками. Например:

> Мы делаем первую лабораторную по системному анализу. Требуется выбрать
> наблюдаемую систему, описать и обосновать её границы, определить среду,
> заинтересованные стороны и их цели, сформулировать проверяемую цель
> системы, а после посещения записать три наблюдения. Помоги создать в
> папке `lab1/` черновики: `README.md` для записки, `stakeholders.md` для
> таблицы сторон и `context.mmd` для Mermaid-контекстной диаграммы. Сначала
> задай мне вопросы о системе и предложи структуру файлов. Не выдумывай
> факты, ответы участников и наблюдения; неизвестное отмечай как
> `[уточнить]`, наблюдения — как `[добавить после посещения]`.

Если задание лабораторной не лежит в командном репозитории, вставьте его
требования в сообщение или передайте агенту нужный контекст. Просите его
редактировать конкретные файлы, объяснять диаграмму и проверять согласованность
записки с таблицей.

Агент не наблюдал вашу систему и не разговаривал с её участниками.
Проверяйте факты, границы, выводы и подписи диаграммы сами. Перед сдачей
просмотрите файлы и diff в Zed или GitHub Desktop, замените пометки
`[уточнить]` и `[добавить после посещения]` своими данными.

В GitHub Desktop просмотрите изменения, введите сообщение коммита и нажмите
**Commit to lab1**. Затем нажмите **Publish branch** или **Push origin**.
На GitHub откройте pull request из `lab1` в `main` и сдайте его по
инструкции курса.

## Подход 2. GitHub Codespaces в браузере

Codespaces запускает облачную среду с редактором VS Code прямо в браузере.
Это удобно, если вы не хотите устанавливать редактор и Git. Создавать и
редактировать файлы можно в редакторе, а изменения отправлять через панель
**Source Control** или встроенный терминал.

### Откройте репозиторий в Codespaces

1. Откройте репозиторий команды на GitHub и создайте ветку `lab1` от
   `main`, если её ещё нет.
2. Переключитесь на `lab1`, нажмите **Code → Codespaces** и выберите
   **Create codespace on lab1**. Перед запуском GitHub покажет, кто будет
   оплачивать среду.
3. Дождитесь запуска. В браузере откроется VS Code с файлами репозитория.
   Создавайте и редактируйте материалы лабораторной, например, в папке
   `lab1/`.

### Сохраните и отправьте изменения

Откройте **Source Control**, просмотрите изменённые файлы, введите сообщение
коммита и выберите **Commit**. Затем нажмите **Sync Changes** или **Push**.
Те же действия можно выполнить во встроенном терминале командами
`git status`, `git add`, `git commit` и `git push`.

На GitHub откройте pull request из `lab1` в `main` и сдайте его по
инструкции курса. Перед сдачей проверьте факты и выводы так же внимательно,
как при работе в Zed.

Codespaces предоставляет облачную среду редактора, но сам по себе не
настраивает Codex. Если нужен агент, подключите совместимое с VS Code
расширение или CLI отдельно и войдите по инструкции этого инструмента.

### Доступность и бесплатные лимиты

Для личных аккаунтов GitHub сейчас включает ежемесячную квоту Codespaces:

| План личного аккаунта | Вычисления | Хранилище |
|---|---:|---:|
| GitHub Free | 120 core-hours в месяц | 15 GB-month |
| GitHub Pro | 180 core-hours в месяц | 20 GB-month |

Эти квоты действуют, если Codespace оплачивается личным аккаунтом. Для
репозитория организации плательщиком может быть организация (если она
разрешила это) или студент — в зависимости от плана и настроек. GitHub
показывает плательщика перед запуском, проверьте его. Если личная квота
исчерпана и платёжные данные не добавлены, запустить среду, требующую оплаты,
не получится. При добавленных платёжных данных дальнейший расход зависит от
бюджета и настроек аккаунта.

`Core-hours` учитывают размер виртуальной машины: на машине с двумя ядрами
120 core-hours — примерно 60 часов работы, с четырьмя ядрами — примерно
30 часов. Хранилище считается отдельно и накапливается за время хранения
Codespace, в том числе пока он остановлен.

По умолчанию Codespace останавливается после 30 минут бездействия.
Непрерывная сессия ограничена 12 часами. Остановленный Codespace
автоматически удаляется, если остаётся неактивным 30 дней. Закрытие вкладки
не обязательно останавливает среду. Сохраняйте файлы и отправляйте коммиты
в GitHub; ненужную среду можно остановить или удалить.

Использованные вычисления и хранилище доступны в
[настройках биллинга GitHub](https://github.com/settings/billing), раздел
Codespaces. Квоты и правила могут меняться: сверяйтесь с [таблицей включённого
использования GitHub](https://docs.github.com/en/billing/reference/product-usage-included),
[документацией по биллингу Codespaces](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces)
и [описанием жизненного цикла](https://docs.github.com/en/codespaces/about-codespaces/understanding-the-codespace-lifecycle).

## Берегите данные

Не отправляйте агенту пароли, ключи доступа, персональные данные или
закрытые материалы собеседников. Обезличивайте примеры и получите разрешение
перед передачей реальных данных внешнему сервису.
